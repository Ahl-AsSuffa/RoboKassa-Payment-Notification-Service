# RoboKassa-Payment-Notification-Service
Небольшой ASP.NET Core-сервис на C#, который принимает уведомления об успешной оплате от RoboKassa, проверяет подпись платежа и обновляет его статус в PostgreSQL.

Возможности:
 - Приём POST-запросов от RoboKassa по адресу /robokassa/notify.
 - Получение параметров платежа из формы запроса.
 - Логирование входящих данных в консоль.
 - Проверка обязательных параметров:
 - OutSum — сумма платежа;
 - InvId — идентификатор заказа;
 - SignatureValue — подпись платежа.
 - Проверка MD5-подписи платежа.
 - Обработка суммы в форматах 150 и 150.00.
 - Подключение к PostgreSQL через Npgsql.
 - Обновление платежа со статуса pending на paid.
 - Сохранение времени оплаты и фактически полученной суммы.
 - Защита от повторной обработки уже оплаченного заказа.
 - Возврат ответа OK{InvId}, необходимого для RoboKassa.
 - Запуск HTTPS-сервера на порту 443 через Kestrel.
 - Как работает обработка платежа
 - RoboKassa отправляет POST-запрос на /robokassa/notify.
 - Сервис получает данные платежа из формы.
 - Проверяются обязательные параметры.

На основе суммы, ID заказа и секретного пароля формируется строка подписи:  
 - OutSum:InvId:MerchantPass2
 - Для полученной строки вычисляется MD5-хеш.
 - Вычисленная подпись сравнивается с подписью от RoboKassa.
 - Если подпись неверная, сервис возвращает ошибку bad sign.
 - Если подпись корректная, сервис подключается к PostgreSQL.
 - В таблице payments найденный платёж переводится в статус paid.
 - Сохраняются время оплаты и сумма платежа.
 - Сервис возвращает RoboKassa ответ:
 - OK{InvId}

Если платёж уже был обработан или не найден, сервис также возвращает OK{InvId}, чтобы RoboKassa не отправляла повторные уведомления бесконечно.

Используемые технологии:  
 - C#
 - ASP.NET Core Minimal API
 - .NET
 - Kestrel
 - PostgreSQL
 - Npgsql
 - MD5
 - HTTPS
 - RoboKassa API

Сервис работает с таблицей payments и изменяет следующие поля:

Поле	Назначение:  
 - order_id	Идентификатор заказа из InvId
 - status	Статус платежа
 - paid_at	Дата и время оплаты
 - amount_paid	Фактически оплаченная сумма
 - tg_id	Telegram ID пользователя

Обновление выполняется только для платежей со статусом pending:

WHERE order_id = @oid
  AND status = 'pending'

Это позволяет не обрабатывать один и тот же платёж повторно.

Перед запуском необходимо указать:  
 - параметры подключения к PostgreSQL;
 - секретный пароль RoboKassa;
 - путь к HTTPS-сертификату .pfx;
 - пароль от сертификата;
 - адрес, на который RoboKassa будет отправлять уведомления.

Пример конфигурации:  
string connStr =
    "Host=127.0.0.1;Port=5432;" +
    "Username=YourUN;" +
    "Password=YourPass;" +
    "Database=yourDataBase";
    
Запуск:  
 - Создать ASP.NET Core Web API или Minimal API проект.
 - Установить пакет Npgsql:
 - dotnet add package Npgsql
 - Настроить PostgreSQL и таблицу payments.
 - Добавить HTTPS-сертификат .pfx.
 - Указать настройки подключения к базе и RoboKassa.

Сервис будет принимать HTTPS-запросы на порту 443.

Рабочий прототип обработчика уведомлений RoboKassa. Сервис рассчитан на интеграцию с Telegram-ботом или другим приложением, где после успешной оплаты необходимо обновить данные пользователя в PostgreSQL.
